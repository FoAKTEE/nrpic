New options, one example input: problems/scalar/sr_stochastic.athinput on core/scalar-2
(with its mode file sr_stochastic_modes.txt; the slow-roll case of arXiv:2512.14649 in
code units, 32^3, nmax2 = 64). Every new option is in that file:

<problem> pgen_name = scalar_field
  id = stochastic            initial slice at N*: homogeneous background (phi0, pi0 at
                             N*) plus the coarse-grained linear perturbations of SPEC 5.3
                             with the corrected delta Pi, from the mode file and the
                             amplitudes of the stochastic sources (needs <scalar_field>
                             noise = mukhanov_sasaki)
  slice_window   = true      false: all modes in with W = 1 (with the kicks off: the
                             initial-value problem without sources, test L3)
  slice_k2       = stencil   k^2 of the Bardeen potential: stencil (discrete linear
                             Hamiltonian constraint at rounding) or continuum
  slice_delta_pi = corrected printed: negative control (first-order Hamiltonian residual)
<scalar_field>
  noise_mode_scale = 1.0     factor on the mode functions (slice and sources); -1 is the
                             mirrored realisation
  con_dcycle       = 1       record <basename>.sf.con.hst: <|H|/[H]>, max, <|M|/[M]>,
                             max, with [H], [M] of arXiv:2512.14649 eq. (abscons), box
                             means of phi, Pi, K, alpha, e-folds (0 or absent: off)
  dump_metric      = true    double-precision dumps with gt_ij and At_ij (layout
                             NRSFDMP2, names in the header; reader
                             python/nrpic/scalar_field.py: read_dump)
  dump_constraints = true    H, M_i, E in the dumps (false drops them)
  dump_magnitudes  = false   [H], [M] and the M_i of the BSSN form in the dumps
  dump_noise       = false   false drops the stochastic fields from the dumps
Track E's dump set (phi, Pi, chi, gt_ij, K, At_ij, alpha): dump_metric = true,
dump_constraints = false, dump_noise = false (17 variables, 2.3 GB per dump at 256^3).
With noise_kick_pi = noise_kick_k = noise_kick_a = false no field is synthesized in the
stages. Options that an input does not name keep the behaviour of release core-v0.3.

Mode file and background for a case: on core/scalar-2,
  python3 tracks/core/analysis/scalar2/make_case.py --case quadratic --nmax2 4096 \
      --kstart 100 --out DIR
(reference python/nrpic/sf_inflation.py; quadratic case in code units: mass =
0.182877655899, phi0 = -2.66679478988, pi0 = 0.0297300406809, box 2 pi/sigma). Track E's
own tables in the same format work as well.

A command line may override only parameters that the input file has.
A mode file started late (--kstart) has another phase per shell than one integrated
from N0 (moduli equal to 1.6e-6): runs that are compared mode by mode must share one
mode file.

Not tested, known limits
------------------------
- No run beyond 128^3 with dumps (256^3: ten steps for the cost only); the inflection
  (USR) case has not been run; no refined mesh; one seed.
- With nmax2 = (N/4)^2 (four cells per shortest wavelength, the set-up of the paper) the
  last shells give a first-order truncation part of the constraints (4.7e-11 and 3.7e-4
  at 32^3); it is absent at eight cells per wavelength.
- The slice satisfies the constraints at first order only; a* = 1 only.
- rng::ModeEntity and the wording of rng.md (request (c) of noise-unit-test-results) are
  not done; keys unchanged.
